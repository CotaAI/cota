# Bot 交付与分享

Cota 以 Bot 为交付单位。先决定交付的是一个持续运行的服务，还是供接收方自行运行的文件。

## 分享服务入口

在 `agent.yml` 设置 `deploy: service`。服务模式当前不开放部署机器的原生文件和 Shell；业务工具按配置与业务授权提供。

```bash
cota run --config ./my-bot --chat-app --host 127.0.0.1 --port 5005
```

本机访问 `/chat/`；对外使用时配置域名和 HTTPS，把聊天链接分享给使用者。
`127.0.0.1` 仅可本机访问，不能直接作为他人的公网入口。可由反向代理连接这个监听地址；已有应用则通过自己的前端接入 Web Channel。
飞书 Bot 通过平台聊天入口交付，不必另做网页。

| 角色 | 责任 |
| --- | --- |
| 创作者 / 服务维护者 | 运行环境、模型凭据、数据备份、工具权限、费用、升级和可用性 |
| 使用者 | 访问聊天入口；按部署规则取得身份和会话权限 |
| Cota | Bot 执行、会话协调、事实持久化、调试与通道适配 |

Cota 本身没有替所有创作者托管服务的中心云平台。使用者分享聊天链接不意味着把部署维护交给 Cota。

## 分享 Bot 文件夹

建议交付：

```text
my-bot/
├── README.md                 # 环境、业务依赖、启动方式与验证场景
├── agent.yml                 # 角色、场景、工具权限、Policy 策略
├── endpoints.yml             # 空凭据或占位配置
├── skills/                   # 业务能力说明与必要资源
├── policy/                   # 审核后的业务案例
├── models/                   # 可选、与配置/案例匹配的训练产物
└── requirements.txt          # 可选业务依赖；Cota 不自动执行安装
```

接收方自用时可设置 `deploy: personal`（电脑和个人云主机均适用）；对外提供服务则设置 `deploy: service`。模式切换需要重新加载配置，不改变既有会话身份校验。

接收方安装对应 Cota 版本与业务依赖，填写自己的 endpoints，然后运行 shell 或服务。
`cota init` 是复制官方模板，不是导入任意 Bot 压缩包；自定义文件夹可直接传给 `--config`。
相对 SQLite 路径按 Bot 目录解析。

分享前剔除个人模型/平台凭据、真实聊天数据、`workspace/`、`files/` 等机器工具工作目录、`.cota/`、日志及本地虚拟环境。
Skill 的资源文件和 Policy 也可能含业务资料，应由创作者决定是否交付。
`.cota/` 中的签名密钥用于已有部署身份，不应该复制给新的独立部署。

官方 init/模板打包会过滤运行状态；手动打包你自己的目录时，不会自动替你清理 endpoints.yml 中填写的密钥。

## 更新一个已经运行的 Bot

1. 保存当前 Bot 文件版本及必要的数据备份。
2. 修改 Skill、角色或 Policy；训练型策略重新运行 `cota train --config BOT` 和 `--check`。
3. 用 shell/debug 和代表性问题验证新行为。
4. 停止旧执行实例，再加载新配置；保持或更换 Store 应根据是否需要延续原会话决定。

保持相同 session_id 和持久 Store 才能接续会话；Web app 还需要保留成员数据库与签名密钥。
新建独立部署时不要复制原服务的用户身份与历史。运行中的 Agent 不会自动采用新 Policy 产物。
当前没有内置版本注册表、自动灰度、回滚命令或 RSI 自动应用流程。

具体部署见 [部署指南](guide.md)，应用身份边界见 [应用契约](application.md)。
