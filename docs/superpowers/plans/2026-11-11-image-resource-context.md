# Image resource context implementation plan

User-approved scope: keep all original evidence; transmit lean working messages and immutable image references at startup/recovery/compaction; load only current images before a model request; support explicit old-version re-read through Pi's existing read factory. Cota owns references, scope and evidence; Pi owns native read semantics, execution and compaction. No new Event/schema, database migration, image-review engine, or alternate agent loop.

Protocol: Cota runtime holds a per-session ContextImages registry, indexed incrementally from durable events. A descriptor has id, absolute virtual path, mimeType and decoded size. Tool image IDs are SHA-256 of exact returned bytes; attachments keep their immutable file IDs. Working messages replace image blocks with concise text references and private cotaImageRefs entries containing index and descriptor. imageResources is a small catalog in startup/prepare responses. RPC image_resource(id) resolves only this runtime's authorized registry, preserving old bytes despite mutable workspace files. Catalog/working projection exclude deferred group inputs.

1. Python tests first: startup before Node is small even with >128MiB history; raw events/state unchanged; same-path versions remain distinct; explicit resource reads return old bytes; wrong session/unknown resources fail; compact/prepare cannot reintroduce Base64; latest input/batch selection and custom adapters preserved.
2. Python implementation: small pi_images.py helper; initial, group initialization, prepare and compact responses all use it. Prepare observes authoritative DST for both transports rather than returning full history from Node. Keep real current image bytes only at model transport boundaries. Existing memory/SQL recovery remains unchanged.
3. Node tests first: official read tool resolves known immutable resources via Operations and callback, rejects unregistered paths in service mode; startup resource references hydrate only current messages before budgets; old versions remain re-readable; real provider wire has correct pixels/tools; comparison batches and Pi compaction work unchanged.
4. Node implementation: extend existing image-context adapter with reference hydration/registration, native read Operations with scoped virtual resource handling. Preserve raw Pi event callbacks and public tools declarations; do not modify Pi packages. Preflight known active image sizes before hydration; frame bounds remain.
5. Verify audited 581-event history read-only: initial frame below128MiB, no provider invocation/no live DB writes. Run targeted and full tests/static checks; update current context/debug docs with clear reference-path semantics and original evidence preservation. Review both scope and implementation before completion.

Verified implementation:
- Python full suite: 1642 passed, 2 skipped; separate final distribution suite: 13 passed (including the added local-import packaging regression).
- Pi source and staged-runtime suites: each 105 passed, 2 platform/dependency skips. Ruff, Python syntax and diff checks passed.
- Original 581-event history replayed read-only: 456 working messages, 62 immutable image versions, 654895-byte startup messages/catalog (0.625 MiB), versus the original 128.283 MiB messages-only frame. Real Pi worker accepted the restored history and completed with an offline model stub, fetching no historical image bytes. No provider call or live session write.
- Review follow-ups fixed with failing-first regressions: verify exact returned FileStorage bytes instead of reopening an authorized path; apply group cutoff before building its initial resource catalog; stage image-context.mjs and all Pi tests in runtime builds.
- Original events, snapshot schema, Pi package versions and compaction algorithm unchanged. Business-review convergence and attachment delivery size are separate work.
