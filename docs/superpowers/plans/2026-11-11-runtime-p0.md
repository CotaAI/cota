# Runtime P0 implementation plan

**Goal:** Bound model waits, deliver public tool-call commentary, and bound retained image context without changing the Pi bridge or adding business state.

**Architecture:** Cota continues to own durable events and configuration. Pi continues to own the tool loop and safe compaction boundaries. Transport diagnostics remain independent Debug records and ordinary logs; no new event types or database tables are introduced.

## 1. Model request limits and diagnostics

- [x] Add failing tests in `tests/llm/test_request_limits.py` using the real OpenAI SDK and an offline HTTP transport: retry policy, stalled requests, cancellation, concurrent diagnostics, and invalid settings.
- [x] Configure `llms.<name>.timeout_seconds` (180 seconds total by default) and `max_retries` (zero by default, explicitly configurable for OpenAI adapters). A total deadline covers SDK retries and backoff. Custom endpoints support a total deadline but no automatic retries.
- [x] Extend `cota/llm/observation.py` with safe request-attempt and response-header timings. Do not label response-header timing as first-token latency; non-streaming calls cannot observe first tokens.
- [x] Keep credentials, URLs and bodies out of ordinary attempt logs. Debug records retain attempts and final response-ready time. SDK retry logic remains the SDK's responsibility.
- [x] Make whole-turn timeout errors descriptive in `cota/runtime/pi_bridge.py` and test that cancellation terminates the worker.

## 2. Durable commentary delivery

- [x] Add failing real-Pi tests in `tests/test_assistant_carriers.py`: tool-call text is delivered once before tool effects, two calls share one assistant message, restored context contains no duplicate text, and checkpoint failures deliver nothing.
- [x] Keep the complete assistant proposal on the first `tool_started`. Emit a linked `bot_utter` for its public text in the same checkpoint; validate its source/text and exclude it from assistant-context projection.
- [x] Preserve existing final replies, tool-generated replies, provenance and Debug links. Test MemoryStore and SQLite, normal/debug mode, history and replay.

## 3. Image-context budgets

- [x] Add failing Node tests for count/byte pressure, protected latest tool batches, defaults and invalid settings. Add real-Pi persistence/replay tests.
- [x] Add `dialogue.compaction.max_images` (8) and `max_image_bytes` (16 MiB). Existing request/token budgets remain in effect.
- [x] Use the existing Pi `findCutPoint` and native `compact` implementation when any budget is exceeded. Reduce the retention target until a complete recent suffix fits all budgets; never split a tool batch or alter raw events.
- [x] Fail explicitly before a model request if the latest indivisible batch alone exceeds a budget. Summaries preserve only actual textual evidence; never invent image-review results.

## 4. Documentation and verification

- [x] Update endpoint, Agent and execution/Debug documentation, including non-streaming timing limits and the difference between preserved evidence and model context.
- [x] Run focused Python/Node tests, then `scripts/check.py` once changes stabilize. No paid model calls, no private Bot credentials or artwork changes, no push requested.
