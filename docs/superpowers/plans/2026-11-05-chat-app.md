# Optional chat application implementation plan

**Goal:** Ship an optional, usable Web chat application for a single deployed Bot, without making the runtime or Web Channel depend on application membership storage.

**Architecture:** `cota/webapp/` is a sibling of `cota/channels/`. Its factory composes the public server factory with an access adapter, application-only HTTP endpoints and static assets. Its SQLite registry stores visitor profiles, conversations, membership and hashed expiring invitations; messages remain exclusively in Cota Store. Core transports consume the existing access contract, including authorization on live delivery. The optional application is enabled by `cota run --chat-app`; ordinary server and external application integrations stay independent.

**Tech stack:** Existing Sanic, stdlib SQLite, existing signed guest credentials, vanilla JavaScript and the existing CotaClient. No new dependencies or build step.

## Accepted scope

- The deployment's Agent fixes direct/group mode. Direct conversations have one member; group owners may invite and remove members. No per-room mode override.
- Visitor credentials are browser-held, expire after 30 days, and are not recoverable accounts. Nicknames are presentation only. Invitations are bearer capabilities, hashed at rest, rotated on creation and member removal, expire after seven days, travel in URL fragments.
- Explicit mention control invokes the Bot in passive groups. Ordinary messages are persisted and broadcast. Reconnection and deduplication use public WebSocket APIs and canonical event IDs.
- No contacts, audio/video, generic IM platform, distributed coordinator, or second message database.
- Preserve the ongoing uncommitted 2.0 development; do not create commits containing unrelated work.

## Browser API contract

All paths below are relative to `/chat/api`; protected calls use `Authorization: Bearer <token>`.

```text
GET /config -> {bot_name, mode, response}
POST /guests {name} -> {token,user_id,name,expires_at}
GET /me -> {user_id,name}
GET /conversations?offset=0&limit=100 -> {conversations:[{session_id,title,mode,owner_id,created_at}],has_more}
POST /conversations {title} -> {session_id,title,mode,owner_id,created_at}
GET /conversations/<id> -> {session_id,title,mode,owner_id,created_at,members:[{user_id,name}]}
POST /conversations/<id>/invite {} -> {invite,expires_at}
POST /join {invite} -> {session_id,title,mode,owner_id,created_at}
POST /conversations/<id>/remove {user_id} -> {success:true}
POST /conversations/<id>/leave {} -> {success:true}
```

App entry `/chat/`; invitation URLs `/chat/#invite=<token>`. Static assets `/chat/app.js`, `/chat/style.css`. Uses global `CotaClient` from `/cota.js` with `{token,sessionId,storageKey}`. No direct access to server ctx, DST, Store or private runtime endpoints from frontend.
