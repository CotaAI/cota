# Runtime efficiency implementation plan

Goal: make long Bot runs incremental to persist, bounded in image traffic, and understandable when waiting or stopping. This implements the user's approved four-point design.

Cota owns durable facts, resource identities and request diagnostics. Pi owns the model/tool loop and native compaction. No Pi source changes or alternate execution loop. Raw events/images remain intact; request-only projections may omit obsolete pixels with explicit provenance, never invent review results.

1. Store/DST: cache canonical event-prefix hashes at the reducer boundary, serialize only uncommitted facts, compare revision and persisted prefix, skip unchanged commits, retain transactional outbox and snapshot boundaries. Full journal validation remains on load/export/audit. Test stale writers, fact tampering, replay equivalence, snapshots, no-op revisions and absence of full replay on append.
2. Image context: retain original evidence, deduplicate content, identify resource versions and explicitly recorded observations. Keep the current image batch visible; replace older pixels with concise references and re-read instructions without implying approval. Apply this before budget checks and through Pi's request hook, preserving tool protocol and provider metadata. Test repeated reads, updated same-path images, current batch, user attachments, restart and compaction.
3. Debug: split immutable large request material from changing diagnostic fields. Store each request body once and update small status/timing/response records; reconstruct the same public Debug JSON on read. Test SQL writes, request retrieval and optional Debug failure isolation.
4. Progress: provide transient execution phase and accurate limit/timeout feedback using existing streaming/diagnostic mechanisms, without new durable heartbeat events. Retain completed work and distinguish the model-decision limit from event count. Test terminal status, continued context and channel behavior.
5. Run targeted red/green tests per component, repository static checks, then the full Python/Node suite. Benchmark read-only copies of the audited session, never modify the user's live DB, restart their Bot, or make paid model requests.
