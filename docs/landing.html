围绕完整 Bot 建设

个人助手、客服和群聊助手，共用稳定的业务与执行结构。

🧩

Skill 业务能力

以 SKILL.md 编写 SOP。Pi 发现目录，模型按需读取并组合多个能力。

📝

对话式 Policy

像写对话一样描述业务判断、能力选择、结果分支和回复，降低标注门槛。

🔎

训练与运行指导

支持 BM25、Embedding、模型判断与搜索策略，每次请求结合当前事实选择业务案例。

⚙️

Pi Core 执行

官方 Agent Core 驱动模型与工具循环，Cota 提供业务指导、工具边界和持久化确认。

🗂️

事件与状态恢复

DST 从事件推导状态，Store 逐条保存事实并维护快照，Trace 用于回溯真实执行。

🛠️

可追踪的工具能力

接入 Python Tool、MCP 或独立工具进程。Skill 文本不替代实际依赖与权限。

💬

单聊与群聊

会话顺序、跨用户隔离、断线恢复；群聊可以被 @ 回应，也可启用受控的主动参与。

🔌

应用入口

命令行、Web HTTP/WebSocket 和飞书。可选聊天应用独立提供会话列表与群成员管理。

📋

调试与验证

同一页面查看 Events、Skills、Model Requests 与 DST，结合真实案例检查业务行为。

把业务规则
写成易读的对话

运营可以从零编写，也可以修改真实对话草稿。案例中的结果是条件，运行时仍以真实工具数据为准。

  • 📝
    业务规则

    描述业务要求、异常处理和回复原则。

  • 🧩
    skills

    按稳定名称表达期望使用的业务能力。

  • 🔎
    result

    写出会影响后续流程的示例结果条件。

  • 💬
    reply

    提供话术示例，不复制案例数据作为当前事实。

业务案例示意，非实时查询

北京现在多少度？
业务判断：需要实时数据，使用 weather 能力。
案例条件：主服务和备用服务都没有取得有效结果。
话术原则：说明暂时无法确认，不编造气温。
回复示例：暂时未能查询到天气，我还不能确认当前温度。
