1定义能力与业务规则

你懂业务，
就能开始教它怎么做。

用 Skill 描述业务能力，用 Policy 写下正确处理问题的案例。缺什么先问、结果不同如何继续，都可以像写对话一样表达。

Bot 把角色、规则、工具和配置组织在一起，模型在执行中选择与组合适合的能力。

看看业务案例怎么写
policy/data.yml一个业务案例
policies:
  - name: 缺少城市时先问清
    steps:
      - user: 帮我查一下天气
      - bot:
          - reply: 你想查哪个城市的天气？

Skill 负责“能做什么”，Policy 指导“这时候怎样做”。

2看清执行，验证效果

每次改进，
都能找到依据。

在 Debug 页面查看对话、工具参数与结果、模型请求和状态。使用真实执行记录定位问题，再修改能力说明或业务案例。

用自然语言写回复要求，交给 LLM 逐项评测。保留结构化结果，比较不同版本的表现。

了解对话评测
一次对话，保留完整证据关键事件示意
→user_utter杭州明天适合户外活动吗？
→tool_started调用天气查询接口
→tool_result保存接口的实际返回结果
→bot_utter基于实际数据给出建议
同一份验证集，对照每次修改。

weather 示例自带 30 个评测案例，覆盖多轮条件、业务回复与异常处理。

05 A FEW QUESTIONS

开始之前，
你可能还想知道。

把适用场景和交付责任说清楚。

Cota 适合谁？需要会写代码吗？

适合已经知道 Bot 要解决什么业务问题、愿意维护运行环境的开发者。你需要能编辑 YAML / Markdown、配置模型服务并启动 Python 应用；业务能力和规则主要写在 Bot 文件中。接入新平台或专用接口时，可能需要编写适配代码。

一个 Bot 和一个 Skill，有什么不同？

Skill 描述一项能力。Bot 把角色、能力、业务规则、工具权限、运行配置和验证案例组织在一起，还需要持续处理会话和回复投递。Cota 围绕完整 Bot 的开发与交付工作。

需要使用 Cota 的云平台吗？

你可以在自己的电脑或云主机部署。分享服务入口时，由你维护服务；分享 Bot 文件夹时，由接收方准备依赖和凭据、独立部署。当前提供开源框架与自行部署的工作流。详见部署指南。

可以接入公司 IM 或已有账号体系吗？

可以使用 Web HTTP/WebSocket、飞书，或通过独立 Python 包接入自定义 Channel。外围应用或平台适配器完成身份认证与会话授权，Cota 处理执行协调、持久化和回复投递。

怎么确认修改后的 Bot 更好用了？

用相同的验证案例运行 cota eval，让 LLM 按每条回复要求评判，并比较不同版本的结构化结果。结合真实执行记录复核关键业务行为。当前支持记录、标注、训练与评测；自动生成并应用优化版本仍是后续方向。
