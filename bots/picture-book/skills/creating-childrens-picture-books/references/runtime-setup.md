# 环境准备与图像工具接入

适用：首次使用本 skill、分享给新使用者、更换 harness（执行模型与工具的运行环境）、模型或图像服务。本指南提供接入步骤与验收方法；不包含通用API适配器，不会仅凭配置文字自动接通服务。

## 先检查，再决定是否配置

先查看实际会话可调用的工具、已连接服务和本地依赖，不要求使用者重复填写已有配置，也不读取或打印密钥。检查需求以当前任务为准：文稿工作不依赖绘图；完整成书则需要以下能力。

| 能力 | 通过条件 | 缺少时怎样处理 |
|---|---|---|
| 理解并执行工作流 | 能读取 SKILL.md 及其引用文件，进行中文创作、修改和工具调用 | 使用支持技能目录或能按指令读取文件的 agent 环境 |
| 工作区与执行工具 | 能读写项目文件、执行排版与检查程序、保存中间结果 | 配置可写工作目录及必要的执行权限 |
| 图片理解 | 实际读取本地图片内容，识别动作、表情、位置、数量和图文冲突 | 使用可看图的主模型，或连接独立视觉工具；仅OCR或文件名描述不足以验收 |
| 图片生成 | 能生成插图，将结果保存为可读取的图片资产 | 连接内置图像工具、MCP工具或服务商API调用脚本 |
| 参考图与编辑 | 能把角色图作为真实图片输入，改变场景，并基于原图做指定修改 | 选择支持图片输入及编辑的接口；仅把图片路径写进提示词不算传入图片 |
| 中文PDF制作与查看 | 可用中文字体、可生成PDF、可渲染全部页面并把渲染图交给视觉能力检查 | 补齐字体、排版库、渲染工具与看图工具 |
| 来源查证 | 对科普、健康、文化等现实主张能读取可靠资料 | 接入检索/网页读取，或使用用户提供的可核验来源；不足处暂不写成确定事实 |

图片理解和生成可以来自不同服务。主模型已有视觉能力时，不需要额外视觉模型。使用云端服务不要求本地GPU；使用本地模型时按其官方要求准备硬件，不给所有使用者统一设定显存要求。

## 平台接入路径

### Cota 绘本 Bot 配套入口

若当前 Skill 随 Cota 绘本 Bot 分发，可使用 Bot 自带的制作程序；其他环境继续使用下方已有工具的接入方式。`default` 是规划与对话模型，`image` 和 `vision` 是配套程序使用的图像能力，并非可直接调用的 Pi 工具名。供应商、模型与凭证由部署配置管理，程序自行读取，不打开配置文件查找密钥。

从实际运行环境说明取得 **Bot directory**、**Working directory** 和 **Python executable**。使用该解释器和 Bot 根目录下 `scripts/book.py` 的绝对路径；不要根据作品目录猜 `../` 层数，也不搜索用户电脑上的同名脚本。以下 `<PYTHON>` 和 `<BOT>` 是占位符，须替换成环境提供的真实值，并按当前 Shell 规则转义路径：

```sh
"<PYTHON>" "<BOT>/scripts/book.py" --help
"<PYTHON>" "<BOT>/scripts/book.py" doctor
"<PYTHON>" "<BOT>/scripts/book.py" init my-book
"<PYTHON>" "<BOT>/scripts/book.py" --project my-book status
"<PYTHON>" "<BOT>/scripts/book.py" --project my-book generate --help
```

三个路径基准需分清：

- Skill 的参考资料和自带验证器，相对于 Pi 目录展示中 `SKILL.md` 所在目录定位。
- Bot 制作程序相对于环境提供的 Bot 根目录定位，与当前 Shell 目录无关。
- 作品保存在 Bot 根目录下 `workspace/books/作品名/`。`--project 作品名` 放在子命令之前；generate/review 等命令的文件参数相对于该作品目录。直接使用 read/write 操作作品文件时，使用作品文件的绝对路径，避免与工具工作目录混淆。

每次 Shell 调用从运行环境的工作目录开始；一次命令中的 `cd` 不会改变下次 Bash 或 read/write 的路径基准。正常创作只需 CLI 帮助和当前阶段的 Skill 资料，不需要通读程序源码。

| 能力 | 配套命令 | 使用方式 |
|---|---|---|
| 环境检查 | doctor | 只检查配置与依赖，不发起付费请求；样页验收仍需实际执行 |
| 项目建立与续做 | init / status | 新任务先建立项目，续做先检查已保存资产和请求日志 |
| image 绘图与修改 | generate | 先写提示词文件；参考图用真实文件的 --reference 传入，具体参数按需查看帮助 |
| vision 图片理解 | review | 实际传入图片并保存观察证据，不能用文件名或全书缩略图代替逐页审校 |
| 中文排版与质检 | build / validate | book.json 的版式字段和示例见 build --help；排版成功不等于审校通过 |
| 附件交付 | deliverables | 返回已验证文件的绝对路径，再交给 send_files；--draft 仅用于明确未验收的审阅稿 |

只查看当前步骤的子命令帮助。按故事与分镜、角色参考、一张样页、其余页面、排版审校的顺序推进。图片网络请求上限 240 秒，Bash 调用需给足时间且不超过运行环境的 300 秒上限。结果未知的付费请求先检查已保存日志与供应商记录，不盲目重试。

以下是配置路径，不代表本 skill 已在所有平台完成兼容性测试。当前已有完整绘本制作经验的是作者使用的 Codex 桌面会话；不等于所有 Codex 版本、账号和操作系统均已验证。Claude Code 与 DeepSeek Harness 需要在目标环境完成样页验收，才记录为该配置可用。

### Codex

1. 通过当前版本的技能管理入口或官方支持的技能目录安装整个 `creating-childrens-picture-books` 文件夹，确认能读取其参考文件与脚本。
2. 查看本次会话是否真正提供图像理解和生成/编辑工具；安装绘图 skill 本身并不会授予绘图服务。
3. 已有内置工具时优先使用；不要为此要求使用者另填API Key。若环境提供 imagegen skill，使用时读取它并遵守实际支持的参数和调用方式。
4. 没有内置能力时，明确缺项，按下方“自定义图像服务”接入使用者选择的服务；不要暗中切换到另行计费的API。

官方参考：[Skills](https://learn.chatgpt.com/docs/build-skills)、[图像生成](https://learn.chatgpt.com/docs/image-generation)。

### Claude Code

1. 将整个目录安装到项目的 `.claude/skills/creating-childrens-picture-books/`，或个人的 `~/.claude/skills/creating-childrens-picture-books/`，使 `SKILL.md` 直接位于该目录下。
2. 通过图片路径或图片附件，实际验证当前模型和工具能看图；不能假设通过第三方模型路由后的会话保留相同视觉能力。
3. 若已有可用绘图工具，直接验收。若没有，接入使用者选择的图像生成/编辑 MCP 服务，或在工作区提供可执行的API调用脚本。参考图输入、图片编辑和结果落盘都必须可用。
4. 确认 Claude Code 能运行该工具、读到输出图，并运行PDF制作与检查命令，再进行样页验收。

官方参考：[Skills](https://code.claude.com/docs/en/skills)、[图片工作流](https://code.claude.com/docs/en/common-workflows#work-with-images)、[MCP接入](https://code.claude.com/docs/en/mcp)。

### DeepSeek Harness

1. 将整个技能目录安装到项目的 `.dsh/skills/creating-childrens-picture-books/`，或使用当前版本支持的个人技能目录；确认技能发现与读取工具已启用。
2. 检查当前选择的主模型、图片输入路由和工具。不能按“DeepSeek”这个品牌名推断是否能看图；若主模型不支持图片，连接独立视觉工具，要求它真正读取原图并返回具体观察和不确定处。
3. 确认绘图插件或API工具支持生成、参考图输入、编辑与落盘。图片上传预览成功并不代表模型已看见它，也不代表有绘图能力。
4. 检查执行工具与文件读写权限，完成样页测试，并记录实际 harness 版本、模型路由与插件版本。

官方参考：[技能加载](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/skills.md)、[项目及版本状态](https://github.com/deepseek-ai/deepseek-harness)。该项目的接口可能随版本变化，执行安装或配置前查阅对应版本官方说明，不照搬过期命令。

## 自定义图像服务：需要配置什么

仅当现有能力不足，或使用者明确指定服务时执行。先问缺少的信息，不让使用者无条件填写两套模型。

| 项目 | 如何填写或处理 |
|---|---|
| 用途 | 视觉检查，或图像生成/编辑；可共享同一服务，也可分开 |
| 连接方式 | 已安装MCP工具名、插件名，或实际可执行的API脚本及调用方法 |
| 服务与模型 | 服务商、官方端点、具体模型标识；平台不公开内置型号时写“平台托管，未公开” |
| 凭证 | 由使用者在服务设置、系统凭证存储或本地环境变量中配置；记录只写变量名或凭证引用，不写值 |
| 输入输出 | 支持的图片输入形式、参考图数量、编辑方式、输出格式、尺寸与本地保存方法 |
| 使用范围 | 需要另行付费的服务与使用者已授权范围；有预算约束时记录预算和停止条件 |

接入步骤：查阅所选服务官方文档 → 配置凭证和实际调用工具 → 验证认证与图片输入输出 → 完成下方样页验收。不同服务的API参数与认证方式不能仅靠替换模型名称通用。

不让使用者把密钥粘贴到聊天里，不把密钥放进 skill、book.json、审校记录或交付文件。现有授权足够时直接继续；只有新增付费服务、外传范围或其他必要授权未确定时才补问。未经明确选择不偷偷换服务或上传参考图。

## 本地排版依赖

优先使用环境已有的等效工具。现有制作路线可使用 Python 3、ReportLab、Pillow、pypdf，以及 Poppler 的 `pdftoppm`、`pdfinfo`、`pdffonts`；另需有权使用并可嵌入的中文字体。其他能完成相同检查的工具也可使用，不把某个系统路径写死。

例如，在项目虚拟环境内安装Python依赖：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install reportlab Pillow pypdf
```

Windows使用 `.venv\Scripts\python.exe`；若环境没有 `python3` 命令，使用实际可用的Python启动命令。Poppler按操作系统的软件包管理方式安装；例如 macOS Homebrew 的 `brew install poppler` 或 Debian/Ubuntu 的 `apt install poppler-utils`。系统安装遵守当前权限要求；本 skill 不要求关闭沙箱或开放全部目录。

字体路径由实际环境发现或由使用者提供。不能依赖原作者的macOS字体路径，也不能把“PDF能生成”当成中文已正确显示。检查脚本在缺少 pypdf 时会跳过部分PDF检查；此警告不代表相关检查已通过，应补齐依赖或使用等效工具验证。

## 小规模验收

新环境在批量制图前做一次；同一工具、模型及配置已有有效记录时可复用。尽量使用本书第一张角色参考图和第一张样页，避免无意义的额外消耗。仅有读权限或仅请求文稿时不触发绘图测试。

1. **生成并保存角色图。** 在简单背景下生成一个原创角色，实际读取图片，核对提示与结果。
2. **参考图生成与编辑。** 真实传入角色图，画同一角色的新动作；随后基于已有图修改一个明确细节。检查角色保持、动作是否改变、指定编辑是否生效，并保留输入输出。
3. **检验读图。** 让主模型或视觉工具观察实际图片，报告可见动作、位置、表情及不确定处。用已知图或人工对照核查，不能只重复生成提示词；视觉工具的观察和证据交给主助手用于审校。
4. **制作一页中文PDF。** 在目标纸张上排入样图和含中文标点的短句；检查字体嵌入、纸张尺寸、缺字、裁切、文字遮挡和清晰度。渲染后实际看图。
5. **记录结果。** 通过才批量制作；失败时定位到连接、模型能力、文件路径、字体或渲染等具体缺项，再修复并重测受影响环节。

在项目中保存 `环境检查.md`，可从 `assets/project-template/环境检查.md` 复制。记录日期、平台及可取得的版本、实际工具和模型（未知不猜）、依赖与字体、测试资产路径、逐项结果和剩余限制；`book.json` 可用 `runtime_record` 指向此文件。样页通过只证明基本通路可用，不代替每本书的语言、图像、事实和印刷审校。

## 能力不足时继续哪些工作

- 缺绘图能力：继续简报、文稿、分镜和提示词，交付时明确尚未完成插图，不用占位画冒充最终绘本。
- 缺读图能力：不能勾选视觉审校通过；配置视觉工具，或明确由人逐页审阅并记录审阅者与范围。
- 缺PDF渲染或中文字体：可准备源文件，暂不声称打印版已验收。
- 接口失败：保留已完成资产，说明具体错误，按服务文档处理；不无限重试，不静默切换模型、供应商或付费方式。

分享给别人时附完整技能目录；环境检查记录和API凭证属于使用者自己的环境，不随技能分发。仅需文稿的使用者可以先用创作部分，不必为了加载 skill 配齐完整成书环境。
