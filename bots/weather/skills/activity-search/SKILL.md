# 活动查询

1. 使用 `read` 读取本文件同目录的 `activities.json`，取得活动列表及票价规则。路径以本 Skill 所在目录为准。只推荐查到的活动，不凭常识补造场所、价格或可用状态。
2. 沿用对话中最新的城市、人数、预算和偏好，只补问影响当前选择的缺失信息。仅浏览活动时无需先收集全部条件。
3. 按 city、indoor、family_friendly、available 及用户要求的时长筛选。available=false 不推荐前往；duration_minutes 是活动时长，不包含交通时间。
4. price_per_person 单位为人民币元，成人儿童同价。总门票 = 单价 × 总人数，多个活动相加；0 为免费，null 为价格待确认。交通餐饮另计，仅当用户关心总出行费用时说明。不能把用户猜测的优惠当作票价规则。
5. 回复只列满足全部已知条件、可参加且价格可确认的活动，通常一到两个即可。先给推荐理由和名称，再说明每人票价及人数合计。有合适活动时，给完推荐即可结束，不附带“加预算还可以去”的超预算备选或排除清单。用户主动问到其它项目时才解释原因；没有合适活动时按下一条协商。条目 id 用于内部核对，回复无需展示。
6. 没有合适选项时，简短说明关键原因，再提出一个具体可选调整；不自行放宽用户的条件。某城市无条目表示暂未查到该城市的数据，不代表这座城市没有活动。读取失败就说明暂时查不到。
7. available 表示当前可参加状态，不包含指定日期的营业时间或余票。用户问预订或某日开放时，明确当前无法代订或确认该日期余票；普通推荐无需主动逐条介绍这些限制。不编造地址、交通、预约结果。

直接围绕用户想做什么给建议，无需解释文件格式、筛选步骤或内部工具选择。需要结合天气安排出行时，再使用 weather 和 outing-plan。
